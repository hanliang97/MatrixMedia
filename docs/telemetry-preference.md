# 匿名统计的显式同意

应用首次启动、升级后没有显式同意标记时，GUI 和 CLI 均不发送匿名打开统计。用户可在 GUI「项目详情」隐私设置中开启；同意写入 `~/.matrixmedia/telemetry-enabled`，下次启动生效。已有安装不根据旧版本的默认开启状态推断用户同意。

`MATRIXMEDIA_DISABLE_TELEMETRY` 非空或 `~/.matrixmedia/no-telemetry` 存在时始终关闭，即使同意标记同时存在。环境强制关闭期间拒绝通过 GUI 开启。关闭时先保留/建立禁用标记，再移除同意标记；不覆盖用户已有禁用文件内容。所有模式读取同一个偏好服务，无额外网络入口或账号数据。

本次决策沿用原禁用标记，增加显式同意标记，使旧禁用设置兼容且默认关闭；不引入数据库或迁移。配置读写失败由调用方报错或停止统计，不降级为默认开启。

## 验证（2026-11-06）

基线 `284e47a`，Node 20.15.1、Yarn 1.22.22。原 `scripts/test-telemetry-preference.js` 在默认偏好断言失败（实际 true，期望 false），最小实现后同一测试通过。补充同意持久化、两个标记同时存在时禁用优先、关闭后清除同意并保留用户文件内容的断言。

适用检查为 `yarn test:telemetry-preference`、`yarn test:telemetry-preference-ipc` 和 `git diff --check`。类型/lint：N/A，根包未配置。发布 GUI/CLI/MCP 链路、真实平台草稿、数据库迁移、打包与恢复演练：N/A，本改动不涉及发布或数据库；全仓门禁本轮未运行。实际 GUI 点击未验证，IPC 授权边界由现有自动化测试覆盖。

审查另指出禁用标记访问异常可能被 `existsSync` 吞掉。以真实循环符号链接新增回归，确认开启同意存在时原实现错误返回 true；改用 `lstatSync` 检查标记本身，ENOENT 才视为缺失，其余错误向上抛出，使统计调用方停止发送。修复后两项适用测试再次通过。符号链接回归仅适用于非 Windows，Windows 该文件系统边界未验证。

回滚代码会恢复旧版本默认开启行为；因此不能将回滚当成隐私默认值保持不变。紧急停止统计可设置环境禁用或保留 `no-telemetry` 标记；不会删除账号、素材或发布记录。
