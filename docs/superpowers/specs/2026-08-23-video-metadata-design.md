# 视频发布元数据语义统一设计

## 目标

消除 `bt2` 同时表示“视频号短标题”和“其他平台正文”的歧义，统一 GUI、CLI、HTTP API、定时发布及历史记录中的视频元数据语义。

## 标准字段

- `name`：任务名称，仅用于发布记录。
- `title`：视频标题。
- `description`：视频简介或正文。
- `shortTitle`：仅供视频号“概括视频主要内容”使用，长度为 6～16 字。
- `tags`：视频标签列表。

## 平台映射

- 抖音：标题使用 `title`，正文使用 `description + tags`。
- 小红书：标题使用 `title`，正文使用 `description + tags`。
- 哔哩哔哩：标题使用 `title`，简介使用 `description`，标签写入独立标签控件。
- 快手：作品描述使用 `description + tags`。
- 视频号：描述使用 `description + tags`，概括短标题使用 `shortTitle`。
- 头条、百家号：标题使用 `title`，暂不写入简介。
- 番茄视频：保持现状，仅上传视频，不写入元数据。

拼接正文时过滤空值，并使用单个空格连接简介与格式化后的标签。

## 兼容策略

发布任务在进入各平台上传器前统一规范化：

- `bt1` 兼容为 `title`。
- `bdText` 兼容为 `description`。
- `bt2Filled` 兼容为 `shortTitle`。
- `bq` 兼容为 `tags`。
- 旧数据仅在缺少 `description` 时将 `bt2` 回退为简介。

新建任务使用语义字段，同时保留旧字段输出，避免现有发布记录、定时任务和上传器在迁移期间失效。上传器逐步改为只读取规范化后的语义字段。

## 入口调整

- GUI：提供“视频标题”“视频简介”“视频标签”“视频号短标题”。
- CLI：提供 `--title`、`--description`、`--tags`、`--short-title`。旧 `--bt2` 在视频号中兼容为短标题，在其他平台中兼容为简介。
- HTTP API：提供 `title`、`description`、`tags`、`shortTitle`。旧 `bt2` 同样按目标平台兼容。
- 目录批量发布：支持标题、简介、标签、视频号短标题列；缺失列按空值处理。
- 定时发布与重新发布：完整保存并恢复四个语义字段。

## 校验

- `title` 保持必填。
- 仅选择视频号且填写 `shortTitle` 时执行 6～16 字及特殊标点校验。
- `description` 允许为空；为空时只写标签。
- `tags` 继续执行现有的平台格式化和数量提示。

## 测试范围

- 元数据规范化与旧字段回退。
- GUI payload 生成和重新发布恢复。
- CLI、HTTP API 参数解析。
- 定时任务序列化与恢复。
- 各平台最终标题、简介、短标题和标签映射。
